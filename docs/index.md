# AceMQ for .NET

AMQP for C# and VB.NET: the same message envelope, the same patterns and the same
metric names as the [JVM libraries](https://acemq.org/), with an API that reads like
.NET rather than transliterated Java.

> **In development.** The envelope contract and its conformance tests exist and
> pass. There is no transport, no publisher and no consumer yet — this library
> cannot send a message. Nothing is published to a package feed.

## Two languages, one assembly

C# and VB.NET compile to the same IL, so both reference the same package. There is
no separate VB library and there will not be one.

```csharp
// C#
var envelope = Envelope.Of("order.placed")
    .CorrelationId("corr-1")
    .Header("x-tenant", "acme")
    .Build();
```

```vb
' VB.NET — the same assembly, the same types
Dim envelope = Envelope.Of("order.placed") _
    .CorrelationId("corr-1") _
    .Header("x-tenant", "acme") _
    .Build()
```

What that costs is discipline on the public API rather than a second
implementation: nothing on the surface that VB cannot call. See
[VB.NET](vbnet.md).

## Why the envelope comes first

A port is only "the same library" if something proves it. The proof here is a set
of fixtures **generated by publishing through the Java library** and reading the
message back at the transport level — not copied from documentation.

Two implementations agreeing with the same prose is not interoperability.
Agreeing with the same bytes is.

That exercise immediately pinned six behaviours no document stated plainly, any of
which would have been a coin flip if transcribed by hand. They are on [the
envelope](envelope.md) page.

## What runs today

| | |
|---|---|
| `AceHeaders` | The header names AceMQ puts on the wire |
| `Envelope` | Identity, causation, attempt counters — and the defaults, which are contract |
| Conformance tests | 7, asserting against headers Java actually produced |

## Where it runs

`netstandard2.0`, which reaches **.NET Framework 4.6.2+**, .NET Core and modern
.NET from one assembly.

That is deliberate rather than conservative. The applications most likely to want
a supported AMQP library are the ones that cannot easily move, and
`netstandard2.0` is the only target that reaches all of them at once. A `net8.0`
target will be added alongside for modern consumers.

## The rest of AceMQ

The JVM libraries — the AMQP core, its Spring Boot starter, the RabbitMQ
management API and the load generator — are at **[acemq.org](https://acemq.org/)**.

The wire contract, the metric names and the conformance suite are shared and
single-sourced there. This site is where the .NET libraries are documented, not
where the specification lives.
